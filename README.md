# YT+YA-MP3

Репозиторий проекта: [mus-yt-mp](https://github.com/vikrk/mus-yt-mp).

Telegram-бот для скачивания видео YouTube в MP3, MP4 или MKV и отдельных треков Яндекс Музыки в MP3 с персональной авторизацией. Владелец подтверждает доступ пользователей; доступны очередь, выбор качества, отмена задач и административная очистка сообщений. Веб-медиатека показывает опубликованные результаты YouTube и позволяет слушать MP3 в браузере.


## Что устанавливается

- Python-бот в `/opt/yt-media-bot`, отдельный пользователь `yt-media`.
- **yt-dlp**, **FFmpeg/ffprobe**, **Deno** для JavaScript-проверок YouTube.
- Отдельный **Xray-клиент** и служба `yt-media-proxy`.
- Загрузка VLESS-узлов из подписки 3x-ui и обновление каждые шесть часов.
- Библиотека Яндекс Музыки в отдельном Python-окружении: авторизация каждого пользователя через код на странице Яндекса и приватное хранение треков.
- nginx, HTTPS через Let's Encrypt и публичная медиатека: список файлов, поиск, фильтры форматов, сортировка, копирование ссылок, скачивание и прослушивание MP3.

Схема подключения:

```text
Telegram API + yt-dlp (YouTube)
        ↓ HTTP proxy с паролем, 127.0.0.1:18189
Отдельный Xray-клиент на сервере бота
        ↓ VLESS TLS / Reality, узлы из вашей подписки
Другой VPN-сервер → Telegram API / YouTube

Яндекс Музыка → прямое подключение к источнику
```

Это клиентское подключение к другому серверу. Собственная панель 3x-ui на сервере бота не нужна. При нескольких узлах используется выбор по задержке. В режиме подписки Telegram API и обе стадии yt-dlp (метаданные и загрузка YouTube) работают через прокси без автоматического прямого обхода. Яндекс Музыка и обновление подписки подключаются напрямую; окружение процессов Яндекса очищается от прокси-переменных. При установке можно выбрать режим **без подписки**: ввод подписки и проверка VPN-сервера пропускаются, Telegram проверяется напрямую, бот работает без Xray.

## Установка с нуля

Поддерживаемая цель: **Ubuntu 22.04 или 24.04 LTS, x86_64**, systemd, root/sudo. Рекомендуется от 2 ГБ RAM и достаточно диска под результаты и временные файлы. Сквозная установка на новой VM пока не проверялась; локально проверены исходники и тесты, Linux-проверки описаны в CI.

1. Создайте отдельного бота через BotFather. ID владельца определится автоматически при отправке `/start` во время установки; узнавать и вводить его вручную не нужно.
2. Подготовьте домен, например `media.example.com`, и DNS A на новый сервер. Если есть AAAA, IPv6 тоже должен вести на этот сервер. Разрешите входящие TCP 80/443 в сетевом экране. Порт 18189 наружу открывать не нужно.
3. Для режима с подпиской подготовьте HTTPS-подписку 3x-ui или отдельную VLESS-ссылку. Поддерживаются обычные URI/base64-подписки с TLS/Reality; Clash YAML не поддерживается. Для режима без подписки этот пункт пропустите.
4. Скачайте репозиторий и запустите установщик:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/vikrk/mus-yt-mp.git
cd mus-yt-mp
sudo bash install.sh
```

Установщик спросит домен и email для сертификата. Установит FFmpeg из Ubuntu, а yt-dlp, Deno и Xray — из официальных GitHub Releases с проверкой SHA256 из метаданных GitHub. По умолчанию выбираются текущие релизы. При отсутствии digest установка останавливается. Установщик не предназначен для повторного запуска поверх существующей установки.

Версии можно задать явно, используя точные теги релизов:

```bash
sudo env YTDLP_VERSION=<tag> DENO_VERSION=<tag> XRAY_VERSION=<tag> bash install.sh
```

Вместо `<tag>` подставьте существующие теги: у Deno и Xray они обычно начинаются с `v`. Установщик выводит установленные версии и контрольные суммы; сохраните вывод для повторяемой установки.

5. В конце установки автоматически откроется мастер сети и бота. Повторно запустить его можно по SSH с интерактивным терминалом:

```bash
sudo /usr/local/sbin/yt-media-setup
```

Мастер предлагает два варианта:

- **1 — С подпиской:** скрытый ввод подписки → проверка конфигурации Xray → проверка подключения через VPN-сервер внешним HTTPS-запросом → проверка Telegram API через туннель → ввод токена бота.
- **2 — Без подписки:** пропускаются ввод подписки и проверка VPN-сервера → проверка Telegram API напрямую → ввод токена бота.

Если проверка соединения или Telegram API не прошла, мастер остановится и токен не запросит. Только после успешной проверки API выполняется настройка бота: ввод токена, `getMe`, проверка отсутствия webhook, затем автоматическое определение владельца. Откройте указанного бота со своего аккаунта и отправьте `/start` в личном чате. Мастер получает числовой ID от Telegram, показывает найденный аккаунт и просит подтвердить его в SSH-терминале словом `YES`. Только после подтверждения сохраняются ID и токен и запускается бот. Старые сообщения, сообщения групп и сообщения от ботов не назначают владельца. Время ожидания — пять минут. При повторной настройке служба бота останавливается на время определения владельца; если настройка прервана, повторите мастер.

Токен и подписку не передавайте аргументами команд. Для HTTP-подписки предусмотрено отдельное явное подтверждение; предпочтительнее HTTPS.

6. Откройте бота, нажмите Start и отправьте одну ссылку YouTube. Выберите формат и качество. Другие пользователи запрашивают доступ; владелец подтверждает его в боте.

## Яндекс Музыка

Установщик создаёт `/opt/yt-media-bot/yandex-venv` и устанавливает закреплённые зависимости из `requirements-yandex.txt`, включая `yandex-music==3.2.2`. Общего аккаунта Яндекса у бота нет: каждый допущенный пользователь подключает собственный аккаунт.

1. Отправьте боту `/yandex` и нажмите «Подключить Яндекс.Музыку».
2. Откройте страницу Яндекса, указанную ботом, введите персональный код и подтвердите вход. Код действует до пяти минут. Пароль и токен в Telegram отправлять не нужно.
3. Отправьте HTTPS-ссылку на отдельный трек: `https://music.yandex.ru/track/123456` или ссылку вида `/album/123/track/456`.
4. Выберите MP3 192 или 320 кбит/с. Для скачивания нужен доступ к треку в вашем аккаунте; альбомы и плейлисты целиком не поддерживаются.

Токены хранятся в `/var/lib/yt-media-bot/yandex-accounts/<Telegram ID>/token.json` с правами 0600; пользовательские каталоги имеют права 0700. Треки сохраняются отдельно в `/var/lib/yt-media-bot/yamp/<Telegram ID>/`. Они не публикуются в веб-медиатеке. До 50 МБ файл отправляется в личный чат, более крупный файл остаётся в закрытой папке; доступ к ней у администратора по SSH/SFTP. Служебные сообщения об ошибках не раскрывают токен.

Отключение доступно через `/yandex` с подтверждением. Оно удаляет сохранённый токен и отменяет собственные задачи Яндекса, сохраняя уже скачанные MP3. При отзыве доступа к боту авторизация пользователя удаляется. Если токен истёк или отозван, подключите аккаунт заново; автоматического обновления токена нет.

Используется [неофициальная библиотека Yandex Music API — репозиторий проекта](https://github.com/MarshalX/yandex-music-api#yandex-music-api).

## Медиатека и доступ к файлам

Откройте `https://media.example.com/mp/`, заменив домен на свой. Страница получает каталог из `/mp/_catalog/`, автоматически обновляет список, поддерживает поиск, сортировку, фильтры MP3/MP4/MKV, скачивание и прослушивание MP3. Для перемотки nginx поддерживает HTTP Range-запросы.

Все файлы в `/var/lib/yt-media-bot/public` доступны посетителям каталога без входа. Здесь сохраняются результаты YouTube. Добавленные администратором через SSH/SFTP файлы MP3/MP4/MKV также появляются в каталоге, если nginx может их читать. Не размещайте в этой папке секреты или приватные материалы. Закрытые архивы и файлы Яндекс Музыки лежат вне веб-каталога; скрытые файлы, вложенные пути и символические ссылки не обслуживаются.

## Проверка и диагностика

```bash
systemctl status yt-media-bot yt-media-proxy --no-pager
systemctl list-timers yt-media-subscription.timer
sudo journalctl -u yt-media-bot -n 80 --no-pager
sudo journalctl -u yt-media-proxy -n 80 --no-pager
sudo /usr/local/sbin/yt-media-vpn-setup --check
yt-dlp --version
ffmpeg -version
deno --version
sudo nginx -t
sudo certbot renew --dry-run
```

`--check` проверяет действующий туннель без изменения конфигурации и нужен только в режиме подписки. В прямом режиме служба прокси и таймер отключены. Для смены режима используйте `yt-media-setup`. Для обновления подписки вручную:

```bash
sudo systemctl start yt-media-subscription.service
sudo journalctl -u yt-media-subscription -n 50 --no-pager
```

Если бот не запущен, сначала проверьте Xray и подписку, затем токен. Не запускайте второй экземпляр с тем же токеном. Если сертификат не выпущен, проверьте DNS, доступность 80/443 и выполните команду certbot из установщика вручную; после успешного сертификата завершите установку служб вручную по `install.sh`. Автоматический откат частично выполненной установки не предусмотрен.

## Настройки и файлы

| Путь | Назначение |
|---|---|
| `/etc/yt-media-bot/config.json` | ID владельца, URL публикации, квота хранилища |
| `/etc/yt-media-bot/telegram-token` | Закрытый токен, права 0600 |
| `/etc/yt-media-bot/subscription-url` | Закрытая подписка, права 0600 |
| `/etc/yt-media-bot/proxy-config.json` | Конфигурация отдельного клиента, права 0600 |
| `/etc/yt-media-bot/proxy-url` | Пароль локального HTTP-прокси, права 0600 |
| `/var/lib/yt-media-bot/access.json` | Подтверждённые пользователи и служебное состояние |
| `/var/lib/yt-media-bot/jobs` | Временные рабочие файлы |
| `/var/lib/yt-media-bot/public` | Опубликованные результаты |
| `/var/lib/yt-media-bot/archive` | Закрытый архив |
| `/var/lib/yt-media-bot/yamp/<Telegram ID>` | Закрытые MP3 Яндекс Музыки пользователя |
| `/var/lib/yt-media-bot/yandex-accounts/<Telegram ID>` | Закрытые персональные OAuth-токены |
| `/opt/yt-media-bot/web/index.html` | Страница медиатеки |
| `/etc/nginx/sites-available/yt-media` | Виртуальный хост файлов |
| `/etc/nginx/snippets/yt-media-locations.conf` | Медиатека, каталог JSON и выдача файлов |

В `config.json` задаются `owner_id`, `public_base_url` и `storage_limit_bytes` (по умолчанию 20 ГиБ). После изменения перезапустите бота. При смене домена обновите также nginx, DNS и сертификат. URL публикации должен соответствовать `/mp/` вашего nginx.

Для YouTube: MP3 128/192/256/320 кбит/с, MP4 до 1080p, MKV до 2160p при наличии у источника. Для файлов до 50 МБ бот отправляет файл и ссылку, для больших — ссылку. Один файл ограничен 3 ГиБ, рабочие данные — 5 ГиБ, необходим запас свободного места. Общая квота учитывает публичные файлы, архив и закрытые MP3 Яндекса. Автоматического удаления результатов нет: владелец контролирует квоту и удаляет ненужные файлы. Каталог YouTube публичный; треки Яндекса приватные. Для скачивания используйте материалы, на которые у вас есть права.

## Обновление и резервные копии

После получения новой версии репозитория:

```bash
sudo bash scripts/update.sh
# Вместе с обновлением yt-dlp, Deno и Xray:
sudo bash scripts/update.sh --tools
```

Обновление запускает тесты и сохраняет предыдущий код, бинарники, скрипты, службы и nginx-конфигурацию в `/var/backups/yt-media-<UTC>`. Оно устанавливает зависимости Яндекс Музыки, обновляет страницу и подключает новые маршруты медиатеки, сохраняя HTTPS-настройки certbot. Если обнаружен нестандартный блок nginx, обновление останавливается для ручной адаптации. Перед перезагрузкой выполняется `nginx -t`; при ошибке восстанавливается прежняя конфигурация nginx. Настройки бота, токены и пользовательское состояние сохраняются. Во время обновления активная конвертация прерывается; обновляйте при пустой очереди. Для отката остановите бота и прокси, восстановите код, службы и nginx из указанной копии, выполните `systemctl daemon-reload` и `nginx -t`, затем запустите службы и перезагрузите nginx.

Отдельно резервируйте `/etc/yt-media-bot` и `/var/lib/yt-media-bot`; это приватные данные с секретами. Храните копии закрыто. При переносе токена остановите старый экземпляр перед запуском нового.

## Разработка

Главный процесс бота использует стандартную библиотеку Python. Авторизация и загрузка Яндекс Музыки выполняются отдельными процессами в `yandex-venv` с зависимостями из `requirements-yandex.txt`. FFmpeg, yt-dlp, Deno и Xray являются внешними программами.

```bash
PYTHONPATH=app python3 -m unittest discover -s tests -v
python3 -m compileall -q app scripts
bash -n install.sh scripts/update.sh
```

GitHub Actions выполняет тесты и проверку shell-скриптов на Ubuntu, проверяет установку библиотеки и HTTP-выдачу nginx: каталог, воспроизведение с перемоткой и недоступность приватных файлов. На Windows проверки POSIX-прав авторизации и HTTP-тест без установленного nginx пропускаются. Локальные файлы подготовки и исходные снимки исключены через `.gitignore`.

Официальные компоненты: [yt-dlp — репозиторий](https://github.com/yt-dlp/yt-dlp), [Xray-core](https://github.com/XTLS/Xray-core/releases), [Deno](https://github.com/denoland/deno/releases), [FFmpeg — репозиторий](https://github.com/FFmpeg/FFmpeg).
